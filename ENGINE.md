# ENGINE - architecture overview

How the game is put together. Details live in the code comments of the file named; this page is the map.
Older design notes and measurements are in the git history of this file.

## Run, build, check

- `node serve.mjs` serves the game on http://localhost:8080. It transforms TypeScript with esbuild per
  request, so there is no build step while developing.
- `npm run build` (`tools/build.mjs`) makes the one bundled file for itch.io.
- `npm run verify` (`tools/verify.mjs`): syntax, encoding, tsc and lint (`tools/lint.mjs`, the CLAUDE.md
  section 2 rules).
- `npm run suite` runs the quick checks with pass / fail; `node tools/runall.mjs --full` adds the slow ones.
- Proof that a refactor changed nothing (save the reference on the base commit, then compare):
  - `tools/worldhash.mjs` - every level's data after load (`--highway 20` drives 20 km of motorway).
  - `tools/simhash.mjs` - every car's state every 0.5 s over 13 deterministic runs (AI, traffic, crash, cones).
  - `tools/renderhash.mjs` - the canvas pixels at fixed moments of 14 deterministic runs (CPU raster).
  - All three use `tools/lib/determinism.mjs`: a seeded `Math.random`, a fake clock and a stepped
    `requestAnimationFrame`.
- `tools/zoomcheck.mjs` measures how much the same patch of ground changes between zooms.

## One frame

`game/loop.ts`, driven by `requestAnimationFrame`:

1. Input: `input.ts` (or the autopilot / demo driver) gives one input state.
2. Fixed-step simulation: an accumulator runs `game/sim.ts` in steps of `PHYSICS_STEP_SECONDS` (1/120 s):
   the player car (`vehicle.ts step`), AI cars (`game/ai.ts`), highway streaming and traffic, contact,
   damage, rollovers, loose objects, wear, race rules and timing.
3. Interpolation of every car between the last two steps.
4. Draw: `renderer.frame()` (world into the art-pixel buffer, then to the screen), then the HUD.
5. Audio update and the fps meter.

THE PHONE REPORT'S GPU AND LAYER NUMBERS (always with `?report=1`; nothing runs without it;
report only). `ui/gpustat.ts`: each report frame gets 22 more numbers after its 13
(`STAT_FIELDS`, named in each post's `stat.fields`): the GPU ground's WebGL time
(`EXT_disjoint_timer_query_webgl2` where the browser has it - a frame a few frames back; -1 none,
-2 disjoint), the FENCES once in `FENCE_EVERY` (60) frames - `gl.finish()` + a pixel read, and the
screen canvas copied into a 1-pixel probe and read, each taken again at once with nothing queued
(the fence's own cost; the work is the difference) - how late the animation-frame callback began,
our whole work (sim, draw, HUD; the gap to the next frame is the browser's), each draw layer's ms
(`render/layerclock.ts` wraps the renderer context's painters into buckets ground, shade, deck,
still, props, overhead, fx, rain, night; `render/screen.ts` times the cars and the art buffer's
blits; `game/loop.ts` the HUD) and the props drawn / trees / props looked at. Each post's `stat`:
the timer's name, the GPU's name (`WEBGL_debug_renderer_info`), cores, memory, the battery and the
CPU pressure where the browser has them, visibility / focus changes, long tasks. A fence makes its
frame wait: `tools/phonereport.mjs` leaves that frame and the next out of the medians and prints
all / slow / p95 medians per column plus the fences. `tools/scratch/_gpustat.mjs` runs the
highway at the phone's size on a desktop (conditions `day;night;rain`, `/skip=` layers).

A frame's game time is whole display refreshes (`game/pacing.ts`, the learned refresh); a frame
stamped before the last one, or 250 ms or more after it, is taken as it is - the first can be
stamped before `main.ts` took `performance.now()`, so its time was NEGATIVE: the menu race's demo
driver (driven with the frame's time, as `?autopilot`) took it as a step back, its clock went below
0 inside a 'wide' window it never opened (`ai/driverDrive.ts`: `state.wideUntil` unset,
`state.wide` undefined), its steer was NaN and the camera car froze, its tyre wear NaN through
every recovery. Since 11-15 (passed) such a frame has 0 ms
(`tools/scratch/_menunan.mjs` hunts the menu race's NaN; `AHEAD=` forces the case).

THE LOADING SCREEN (the default since 11-14; `game/loading.ts`, its picture
`menu/loadscreen.ts`): a START (`menuflow.ts launch`) or RESTART (`session.ts doRestart`) in a
session puts a DOM screen up at once - the track's name and a bar, in the menu's pane, faces and
colours; it takes every tap and touch, and the keys are ignored while it is up (`controls.ts onKey`).
A frame paints it, then the work runs behind it a stage a task, each after a painted frame: the level
build (`controls.ts enterLevel`, a new level only), the rest of the switch (`settleLevel`: cones,
marks, the restart), the session (`launchSession`: car, livery, tyres, the restart), the field lined
up (`startField`, its own task as before), the fly-in started with its whole-level picture painted
and uploaded to the GPU (`renderer.readyFlyIn`), then every ground tile the fly-in will show planned,
painted and uploaded a slice a task (`renderer.planStartGround / paintPlanned / uploadPlanned`,
`render/tilesDensity.ts`: see `render/tiles.ts` below). The bar
moves at each stage and eases through a long one on the compositor (paced by the time that stage took
last). The screen stays up at least 300 ms (a quick load flashed it); the full bar then turns the
press's electric blue and blinks twice (160 ms, as a pressed menu button: `pixelstyle.ts
PRESS_BLINK_MS / PRESS_BLINK_CSS`), then the screen fades (250 ms) over the fly-in's hold. While the screen or the fly-in is up, `loop.ts` steps no sim (`holdRace`: no race
time, the AI and lights' clock still, the walkthroughs wait) and draws nothing behind the screen; the
countdown starts on the first frame after the fly-in. The race behind the menu never shows it.

NOTHING REDONE AT A START (the default since 11-14): a
START on a new level ran the restart twice - the level switch's (`controls.ts settleLevel`) and the
launch's own (`menuflow.ts launchSession`): two cones resets, two field line-ups, the first fly-in
picture thrown away. With the switch the switch's is skipped (`settleLevel(false)`) and the launch's
is the one. A RESTART reuses the fly-in's whole-level picture (`render/flypicture.ts
keptFlyPicture`, one kept, dropped when memory is short): it is painted afresh only when what it
shows can differ - another level or layout, a rebuilt patch list, the scenery water drawn (a pond
frozen over is an ice twin, left out of the picture), the screen's px a metre; the endless
road's every time. The picture holds no weather, time of day, light or wear (laid over it as drawn),
and a level's own mud dried in a race is put back before the fly-in.

RESETS (`game/session.ts doReset`; the endless road's guard in `game/sim.ts stepEndlessHighway`; a
big cut's put-back in free practice, `game/order.ts putBackCut`). A circuit or stage: RESET_BACK (4
m) behind where the car last was on the road, on the edge it left by, nose 5-15 deg back on; the
joker lane the same along the lane; the endless road RESET_BACK back on our hard shoulder (a verge
or lay-by on a road without one), the traffic within 30 m cleared, and the guard (wrong way, off the
road, an exit taken) 6 m short; levels with no road (the Lab) the breadcrumb ~2 s back. All of them
(the default since 11-15, `game/resetspot.ts`) never ahead of where the car is when the reset comes - a circuit, stage or joker reset from where the car is now
when that is further back than where it left the road (`notAheadOf`), the endless road's guard from
the car's own road distance (`highway.ts highwayRespawn(level, fromS)`, `respawnBehind`); a spot
with a car on it (the racing AI; on the endless road the police - the other traffic is cleared as
before) gives way to the next free one FREE_STEP_M (6 m) further back (`firstFree`, up to 40 tries;
a stage never into its gap between the stop zone and the run-up, `lapBack`), the guard's rolling
put-back keeping 1.5 s of its speed clear ahead; the police are not cleared from round the spot
(`traffic.clearAround(..., true)`: they go only when wrecked or after a bust). Your resets only (the
AI's own: `game/ai.ts aiReset`). `tools/scratch/_resetback.mjs` tries each mode.

STUCK AI AND TRAFFIC. A racing AI first drives itself out (`ai/driveOut.ts`: nearly still 1.2 s ->
reverse 1-1.5 s with the wheel turned toward the road; three tries inside 15 s = `giveUp`, read by
`tools/aifieldcheck.mjs` only). The game (`game/ai.ts stepAIStuck` -> `aiReset`, `game/aistuck.ts`;
the default since 11-15) puts it back only when TRULY stuck - STAYED within 5 m of one spot for 6 s
(not queued: you, a highway car or a racer not itself stood put over 1 s, close in front, facing its
way within 60 deg and under 2 m/s - a racer stood put in front makes a pile-up, put back as one; not
pulling away: forwards and gaining since the watch began, never backed up), or NO PROGRESS: under 4
m/s and not queued with no 3 m of race progress (`_prog`, the highway's `_hwf.s`) in 10 s; never
while the start holds it or a crash plays out - or on the highway 8 m off the carriageway for 3 s
(40 m out at once); a rolled AI once still 1.5 s and a too-injured one after its pause also (those
at the old spot: 4 m behind where it last was on the road, the highway's 15 m back on the hard
shoulder, `highwayrace.ts hwPutBack`; under test, (since 11-15, passed), `FIX.aireset`: by the stuck
put-back's rules below). Its stuck put-back is your reset's:
from where it last was on the road but never ahead of where it is (`resetspot.ts notAheadOf`), the
next spot 6 m further back while a racer is on it (`firstFree` with the AI's own size and the other
racers, `aistuck.ts freeLapSpot`); the highway's hard-shoulder spot (`hwPutBack`, 15 m back) stepped
back 6 m at a time until clear of you, the racers and the traffic, 1.5 s of its rolling speed clear
in front (`freeShoulderSpot`: `hwPutBack`'s own test reads each car's `_hwf`, which traffic cars do
not have). Highway traffic: a physics car under 1 m/s counts `deadT`; out of view past 6 s it is
recycled (`ai/trafficStep.ts leaving`); a wreck brakes with its hazards on. A highway car standing
stuck 6 s goes in view too (recycled, rejoining off screen): its own clock (`slot.stuckGoT`,
`ai/trafficStep.ts noteStuckCars`) runs only while it is still (`deadT` running) and did not stop on
purpose (broken down, at a pump), is not a police car (their own rules) and is not queued
(`findLead`: a car within 8 m in front under 2 m/s) - a car queued behind a wreck starts from 0 when
the wreck goes.
`tools/scratch/_stuckai.mjs` measures every mode, `_stucksum.mjs` checks the logs,
`_stuckshot.mjs` photographs it. The highway's off-road put-back (`highwayOffTooLong`, 8 m out 3 s or
40 m out; the default since 11-15) puts it back as the stuck put-back does, through
`freeShoulderSpot` (two racers put back in one step landed on one spot: the first's reset clears its
`_hwf`, which `hwPutBack`'s test reads).

THE HIGHWAY RACERS AND ONCOMING TRAFFIC (the default since 11-15; `game/ai.ts roadCtx` gives the
driver `DriveCtx.road` on the endless road). The driver reads the cars round it
(`ai/driverTraffic.ts carsStep`) in a box on its own heading - 8 m either side, ahead 8 m + the
closing speed x 2.6-3.8 s by skill; on the endless road, by the road frames every car carries
(`_hwf`: distance along, offset across, speed along the road), so a car round a bend is ahead,
not off to the side. On a two-way road (`geo.oppL`, the middle line; none behind a central
reservation) `ai/driverOncoming.ts ownSideCap`: the nearest oncoming car ahead on the other way's
side, its closing time judged (off by up to 35 % for a skill-0 driver, one draw from the driver's
own random stream per oncoming car; exact at skill 1); within KEEP_S (4 s) - or KEEP_S + PASS_S (8
s) while the racer is on its own side, so a pass needs that much clear road - the racer's lateral
target is capped inside its own lanes (its side 0.3 m short of the middle line), crossing back at a
move's rate, and `followAhead` drops any way round a car that is in the other way's lane.
`tools/scratch/_hwdodge.mjs` counts what the racers hit.

THE AI'S SLIDES BY THE GROUND (the default since 11-15, was `?aislide=1`; `ai/driverSlide.ts`). The
tyre law writes each axle's slip angle at its lateral peak this step to the telemetry
(`physics/wheelspin.ts axleLaw`, `car.t.aPeakF / aPeakR`: tarmac ~0.12 rad, gravel ~0.19, sand
~0.16, wet, snow and ice the 0.10 floor), read only by the AI. On ground under
`SLIPPERY_MU` (0.7: not tarmac, wet or dry): a rear slide in a corner going the corner's way (the
car rotating as the line turns) is HELD on the throttle at 1.25 x the rear peak (0.15-0.30 rad;
`driverSteps.ts driftHold`, the loose hairpins' drift law, now any corner, every rear- or
four-wheel-driven driver) while the edge is further than 2 m x sqrt(0.6 / mu) away; caught past
1.8 x the hold; a slide not held caught past 1.6 x the rear peak (never under the 0.18 rad of
before), the understeer lift past 1.3 x the front peak, the slip feel's angles x the rear peak over
tarmac's. COMMIT OFF TARMAC (`line.ts commitOf`): a 2WD car plans 1.12 x the corner grip where the
line's ground is mu 0.25-0.7 (gravel, grass, sand, mud, snow; not ice). THE KERBS (`line.ts
kerbReach`): beside a kerb the line may come to 0.6 m of the road's edge (was 1.6 m everywhere; the
kerbs lie outside the edge), and the driver's lateral clamp allows the line's own place
(`driverDrive.ts targetEdge`). MISTAKES THAT SLIDE (`driverSlide.ts slideLimits`, `driverLane.ts
applyMistake`): while a 'late' or 'throttle' mistake runs in its corner the catch is x (1 + 1.5 x
its severity), nothing is held, a 'late' one has no understeer lift, and both are twice as big
(`MIST_GROW`). `tools/scratch/_aislip.mjs` measures it; `_aislideshot.mjs` photographs it.
MISTAKES THAT SPIN (left as built, no owner decision; `driverSlide.ts spinChance`, `spinSteer`): a
'late' or 'throttle' mistake is drawn as one that spins with 0.25 x (1 - skill) (the driver's own stream); then its slide
is never caught (no catch, no understeer lift) and past the apex the throttle is held 1.2 s with the
wheel held 0.7 of the lock into the corner. MEASURED: the cars do not spin from it (TODO-DONE
bug 9: 0 spins in 160 runs), so it is inert in practice.

THE PACE DIAL AND THE PRESETS (the default since 11-15; `ai/tune.ts`). A seventh AI DRIVERS dial in
the setup panel, PACE (0..1, 0.5 = x1): every driver's speed plan - the corner grip (`line.ts
K_CORNER`) and the braking grip (its `kBrake`) - x `paceOf(pace)`, 0.8 at 0 .. 1.3 at 1, rounded
to 0.01 (`traits.paceK`, `profileOf`'s fifth argument; the plans are cached per value). Each
difficulty's PRESET (`tuneOf`) is its centre (`SKILL_CENTRE`, `RISK_CENTRE`, `AGG_CENTRE`) + 0.10
skill and + 0.03 risk, aggression and PACE (0.53, x1.02) - the owner's live tuning, the same on
every difficulty so each harder one stays quicker. The shift is on the preset, not the centres: the
centres are also the reference a driver's pace-by-skill is read against (`ai/traits.ts`), as the
owner moved the dials. `_aislip.mjs` PACE=x measures laps at a dial.

THE ONCOMING CAR AND THE PLAN (under test, (since 11-15, passed), `FIX.rollfix`): where a racer means to be
across the road is kept to its side while an oncoming car keeps it there (`driverDrive.ts
plannedLat`, ai/driverOncoming.ts keepMax) before it reads the cars; an oncoming car beyond that
limit is passed, not followed (`driverTraffic.ts passingOncoming`); the gap picker's room and the
stopped-car brake's plan never go into the other way's lane then. `tools/scratch/_rollstop.mjs`
measures rolling starts.

A STOPPED OR MUCH SLOWER CAR IN THE WAY (since 11-15, passed;
`ai/stopDodge.ts`). A car ahead HALTED (`driverTraffic.ts haltedAhead`: under 3 m/s, or slower than
max(5 m/s, half my speed) AND under half the racing speed where it is - my plan there; not coming
back at more than 2 m/s; and NOT PULLING AWAY: speeding up under 1 m/s/s along my way, read with its
braking, `dodge.ts readGain`; and none at all within 2 s of my own getaway, `goT`; under test,
(since 11-15, passed): none through a rolling start's formation and 2 s past its green, `heldT`, and
"much slower" under half my own speed with no 5 m/s floor) is read, with the switch, where it STANDS
ACROSS THE ROAD held to my point (`placeAcross`: off the line at its point + the line's place across
the road there - the line's here), the frame the steering keeps off the line (`driverSteps.ts
offRoad`): read off the line at its own point, a way round planned 3.5 m off the line here ended on
the car where the line crossed the road. Those cars are kept (`CarsAcc.stopped`) for `stopCap`:
while the car's REAL body (`rejoin.ts lateralOf`, not its dodge target) is still in line with one
(within `dodge.ts clearOf`), its speed is capped to what misses it braking at 0.7 of its full
braking - stop 1.5 m short, or reach it no sooner than the time to get across to the planned side
(0.3 s + the m to go at `SWERVE_RATE`) - never under 3 m/s when a way round is planned (held to a
crawl it could not steer out); the room judged off by up to 20 % at skill 0 (one draw from the
driver's own stream per car), exact at skill 1. While in line, going round is a move (`conflict`:
the dodge at the swerve's rate, the steering uncapped by the soft rejoin). Clear of it: no cap. A
stopped car never takes the line's priority from me (`alongsideCar`'s give-way is for racing cars
only). Two plain guards ride on the switch: the wide-window read with the driver's clock below 0
(`driverDrive.ts targetEdge`: no window set -> the usual edge) and a recovery clearing a NaN tyre
wear (`game/sim.ts clearBadWear`: the set's wear at the event's start, 0 with none).
`tools/scratch/_stopsum.mjs` (a car stopped across the line, STOPDODGE=1) and `_pileups.mjs` (a field's
touches and incidents) measure it.

THE SMOOTH FLY-IN (the default since 11-14; `render/flylayers.ts`): zoomed out, a fly-in frame
drew every prop and loose object one by one. With the switch, the layers that hold still while the
field waits at the lights - the deck (run-off, kerbs, bumps, paint), fence, barriers, props, the
tunnels' ground, the loose objects and tape - are painted into pictures, and the props over the
cars (canopies, bridge decks, gantries) and the bridges' ground into a second set; the frame draws
those (smoothed) in their place (`render.ts drawWorldLayers`, `screen.ts drawSharpCarLayers`).
The fly-in's path (`camera.ts flyViewAt`) up to zoom 0.1 is cut into sets 1.25x apart, each covering
its part of the path's views at the art buffer's px a metre at its top zoom, so each hand-over
(to the next set, then to the live drawing) shows the same picture. All are painted behind the
loading screen (`renderer.readyFlyIn`; without it on the fly-in's first frame) and let go as the
zoom passes them. The marks, the pulsing arrows, the cars, effects, night and weather stay live.
Only while the start is armed and not green; never on the endless road; a frame whose view leaves
its set's pictures is drawn live. The pictures are painted one at a time in one scratch canvas and
kept as image bitmaps (a WebKit canvas drawn into another is copied at each draw; at most one
picture's canvas is held), within 24 MB together and 2048 px a side (past either, fewer px a
metre: softer); a refused canvas or bitmap is noted, never thrown. `renderer.flyStats` and the
`?report=1` post's `flySets` (with the switch) count the sets, their MB, the frames drawn from a set
and those of a fly-in drawn live (`live`, and `liveWhy`: every zoomed-out frame drawn live is
counted). The field counts as still while the start is armed and not green, or while the loading
screen's fly-in holds the race (a solo practice has no lights).

THE BOOT BAR (the default since 11-15; `index.html` #bootbar, `game/bootbar.ts`): the loading
screen at the page's first load. A tiny inline script in `index.html`, before the first paint, puts
up the loading screen's pane - LOADING, the owner's logo (the main menu's; until it has loaded, the
name in words, RAC3R with its 3 big and in the logo's blue, in the logo's box so nothing moves) and
the bar - over the boot screen (its look copied there in plain CSS from `menu/loadscreen.ts`, as
the code has not loaded). Its words use their own copies of the
menu's faces (VT323, Press Start 2P with Silkscreen's digits) with `font-display: block`: the pane
and the bar show at once, the words when their faces have loaded (a face slower than ~3 s shows a
monospace stand-in until it comes). The bar eases on the compositor toward the code's share of the
whole wait, over the time the code took on this device the last time (`localStorage
rac3r.bootbar`, written by `game/bootbar.ts`; 3 s the first time), so it moves while the bundle
downloads and while `main.ts` builds the world and the menu. When `main.ts` is done (`endBootBar`)
the code takes the screen over (`loadscreen.ts takeBootScreen`: the loading screen's own
controls) and eases on through the menu's wait - its first frame drawn, then the fonts its text
asked for (a cap of 8 s) - then the bar fills, flashes blue twice and fades into the menu
(`loading.ts flashThenHide`, the loading screen's own ending). The logo and the track thumbnails
are not waited for: the menu never waited for them, and holding for them made the menu later
(TODO.md). The menu race runs behind the bar as without it; the loading screen is never up at the
same time (a START needs a tap, and the bar takes every tap). With no menu (`?menu=0`, the tools)
the bar ends at once over the boot tap. A failed code load takes it down so the error shows.

THE NIGHT FLY-IN (the default since 11-14): two parts.
- THE CANOPY CUT (`render/canopycut.ts`; game-wide: every level, in race and in the fly-in, with or
  without the fly-in): the night layer puts its
  dark back only over the canopies a light may reach. The still lights (lamp pools and heads, the
  event lights that stay put, `eventglows.ts noteStillEventLights` through a probe painter) are
  walked once per level through the prop grid (`propgrid.ts visitPropsInBox`; again when the props,
  the lamps or the level change), each tree keeping its gap to the nearest; the moving lights
  (every car's beams and glows, `light.ts carLightReachM`; sparks; trains; caravans; a knocked
  lamp's head) are walked each frame. A tree within 3 light-map px of a light is traced; a canopy
  no light reached is already exactly the dark, so the pixels are the same. Every canopy on a map

## Sound (`audio.ts`)

All sound is synthesised with Web Audio (no sound files); `?noaudio=1` never starts it. One
context, made in the first tap (`menuflow.ts start / launch`), every voice into one master gain:
the pause menu's SOUND slider and MUTE (and the HUD's VOL button) set that gain and are remembered
(`localStorage rac3r.vol`, `rac3r.mute`; the default 50 %). Only your own car is heard: the engine
(three oscillators -> soft-clip shaper -> low-pass -> formant, pitch from rpm and cylinders), the
tyre squeal and the surface textures and bumps (one looping noise buffer through band-passes).
`game/sim.ts updateAudio` drives them once a frame after the sim, fenced by a try (a throw never
stops the frame). No other car makes a sound, nothing is panned and there is no Doppler.

THE POLICE SIREN (`?siren=1`, `FIX.siren`, under test): `game/sirens.ts stepSirens` (each frame,

## The car (`vehicle.ts` and `physics/`)

A top-down two-axle model with four tyre temperatures. `step(car, input, dt)`, in order:

1. `steerFrontWheels` - steering with speed-sensitive lock and self-aligning (`physics/powertrain.ts`).
2. `runPowertrain` - reverse, gears and shifting, engine rpm, throttle and brake demand.
3. `computeAxleLoads`, `computeLongitudinalDemand` - weight transfer and drive / brake per axle
   (`physics/loads.ts`).
4. `computeWheelForces` - each axle's WHEEL SPEED is state (`car.wU`, m/s at the tread), turned by the
   engine (its inertia through the gearing while the clutch is in), the brakes and the tyre, in 4
   implicit substeps (`physics/wheelspin.ts`). One combined law: longitudinal slip and slip angle,
   each over its peak (later on loose ground: `peakK`), make one slip whose force follows the lateral
   curve's shape (`curveFactor`: up to the peak, down to `slideGrip`), split by each one's share - pure
   cornering is the old curve, a locked wheel slides straight on, a wheel held at the peak keeps some
   steering. ABS dumps / snaps back / creeps (9-18 pulses a s); the rear watches its whole slip (EBD).
   AWD axles are coupled (a viscous centre). Revs and the rev limiter follow the driven wheels. Grip
   by load / aero / temperature, relaxation and ploughing: `physics/tyres.ts`. (Replaced 11-02: a
   friction circle + a sliding law with the slip GUESSED from demand vs grip, and an ABS that capped
   the brake under grip - locked = ABS stops, no steering under ABS; `tools/scratch/_rootbench.mjs`.)
5. `ploughingForces`, `stabilityControl` - understeer plough and the ESC / TCS aids.
6. `bodyAccelerations`, `integrateYaw`, `lowSpeedBlend` - body motion; a blend near standstill.
7. `updateTyreTemps` (`physics/tyreheat.ts`), `advanceCar`, `writeTelemetry`. A tyre heats by slip
   work (uncapped: sliding, spinning, locking, and a gripping axle's rolling scrub) and by FLEX, a
   warm-up toward 85 C read from how hard its axle works. The flex (`flexWork`, the default since
   11-14) reads the brake pedal's force with the cornering force, against the axle's static load
   (downforce no longer hides the work), on a locked axle too (its braking only); the handbrake
   stays out. Measured (`tools/scratch/_frontheat.mjs`, `_heatcases.mjs`, `_heatlaps.mjs`): five
   hard stops leave every car's fronts at 60 C or more (ABS cars 33-50 -> 62-76), racing laps
   within the runs' noise of before, wheelspin and donut heat unchanged.

The mods seam: every car has `car.mods` (`cars.ts defaultMods`: power, shiftTime, inertia, gripLat,
gripLong, brakeTorque, mass, rigidity), all 1.0 by default. Upgrades and tyres change these multipliers;
the model reads them and nothing else.

Surfaces come from the ground under each wheel (`world/wear.ts groundAt`): the surface's grip and drag,
any cover (snow, ice, puddle) and the wear state of the cell. Grip is one sample per axle (`car.surface`
is the rear's); each wheel's MARK and SPRAY come from the ground under that wheel, read by `stepWear`
before its pass (`car.wheelSurf`, carWheels order; `world/wheels.ts CORNER_OF_WHEEL` maps a wheel
to its damage corner). A lost wheel's tyre reads 0 C and its axle's temperature grip is the other
tyre's.

Bushes are ground too: the `bush` surface (its `brush` drag grows with speed,
`physics/tyres.ts`), laid as patches by `world/bushplan.ts` from each level's plan
(`world/levels/bushes.ts`), flattened to long grass by passes (`wear.ts BASE_WEAR`); a wheel
entering a bush cell may puncture or scratch that corner (`world/bushes.ts`). Drawn by
`render/ground/bushes.ts` (squares in the trees' pixel style: shadow, lit squares, shaded side)
over the `bush` art. A few leaf tufts per bush are drawn over the cars
(`render/bushtufts.ts`, in the overhead pass).

Car systems (C): every puncture source (big hits in `damage.ts`,
heat / wear bursts, debris, nails, bushes) ends in `damage.ts`, which starts a LEAK in
`physics/tyrepressure.ts` - a burst flat in ~0.5 s with a sharp pull, a slow one (`car.burstSlow`)
over 10-30 s. Each tyre's pressure sets its axle's grip (1 -> 0.7 flat -> 0.45 on the rim), a pull
toward it and extra rolling drag, folded into `car.wreck` by `damage.ts derive`; driven flat
the rubber comes off by a chance rising with the metres run flat (half by ~1 km). `damage.ts stepDamage` runs it each physics step
(player `game/sim.ts`, AI `game/ai.ts`). METAL ON HARD GROUND (`world/metalscrape.ts`): a rim, or
a rolled body sliding (`roll.ts car.sparks`), sparks and may break each new wear cell a grade
(race tarmac -> tarmac -> broken) through `gougeCell`; a rollover impact has its own chance; a
rim scores a pale mark (`MARK_GOUGE`, `marks.ts`). Drawn by `render/tyrelook.ts` (the tyre
squashes progressively with its air, a rim bare), puffs / shreds / rim sparks in
`render/particles.ts`, the HUD tyre ring by pressure (`hud/gauges.ts`), `?dev=1` line `air`.
Tyre spikes (a police stinger, `world/stingers.ts`, drawn by `render/stingers.ts`) on the Lab and Test Track burst every wheel that rolls on. The Lab's
flip ramp (`world/flipramps.ts`, an armco end; `roll.ts tripCheck` asks it) rolls a car run up it.
ENGINE: `physics/engineheat.ts` keeps each car's engine C, radiator
water, oil and a seize timer, stepped by `damage.ts stepDamage` (every car from the start). Heat
in by throttle x revs (`car.throttleUsed`, set by `vehicle.ts step`); out through the radiator
(thermostat from 87 C, the water left, airflow by speed + rain + wheel splashes) and the block.
A front hit (`damage.ts hit`: the harder-hit front corner's share 0.15+) cracks the radiator
(empty in 4 min .. 40 s), a hard one (0.35+) or a rollover impact may crack the sump. The
leak is WATER: ~60 wear cells a radiator under the nose become the tyres' water (`world/puddles.ts`
rules, the GPU field's look), closer together the worse the leak. Power fades 115 -> 130 C to half (folded into
`car.wreck.power` by `derive`); 10 s at 130 C or with no oil SEIZES it (power 0; an AI resets:
`tooInjured`). Speedo lights `hud/enginelights.ts`; exhaust, backfires, steam and engine smoke
`render/enginesmoke.ts` (pipe spots per car kind, `EXHAUST_SPOTS`); `?dev=1` line `eng`.
OIL: `world/oil.ts` - a wear cell's cover 'oil' like the tyres' water
(`wet.ts oilSurface`: a third of the base's grip; drawn by the GPU field as kind 5, like ice
but purple). Spilled by a cracked sump (`engineheat.ts`), a big hit or a rollover impact
(`damage.ts` -> `crashOil` / `rollOil`); soaked up by loose ground; never dries. A pass
through it may spread it a cell the way the wheel went (`wear.ts stepWear` notes each wheel's
motion); oil beside water runs into it 50:50 a second (`stepOil`); each spread a generation
weaker (`cell.oilGen`).
DEBRIS: `world/debris.ts`. A corner's hit of 0.3+ may knock off a
part (`damage.ts hardHitCorners -> crashDebris`): a bumper (end-on, one an end), a wing or a door
panel, queued on the car (`partSpawn`) and thrown by `game/sim.ts throwParts` into the loose

UNDER THE SKIN (under test, `?underskin=1`, `FIX.underskin`; `render/underskin.ts`): a car drawn

## Drawing (`render.ts` and `render/`)

- Pixel art: the world is drawn into a low-resolution art-pixel buffer (about 15 art px per metre at
  zoom 1) and blitted to the screen with smoothing off. The camera is snapped to whole art pixels and the
  leftover fraction is applied when blitting. The HUD is drawn afterwards at full resolution.
- `render/camera.ts`: follow with look-ahead, speed zoom (`ZOOM_MIN` 0.30), the level fly-in and the
  whole-level overview picture used during it. The car is never drawn under a
  HUD piece: after the follow and the zoom, `clearHud` moves the camera just enough that the
  car's box on screen clears every piece the HUD draws now (`hud/keepclear.ts hudKeepout`: the
  button row, the panels, the minimap, the aid chips on a car with that aid, the pedals with touch
  controls). Each piece pushes toward the middle along one axis, ramped in over 32 px as the car
  comes alongside, worked out again where the push moved it (up to 4 passes); the camera follows
  that push with its speed changing at most 3 px / frame / frame (`render/hudclear.ts
  followPush`), taken whole only after a teleport, so the view never jumps. Not avoided: the
  steering stick under the thumb, the passing notices, the speed camera's flash, the finish flag.
- `render/tiles.ts`: what lies over the floor and zones (track ribbon, lanes, patches, covers,
  wear, kerbs) is painted into cached tiles within a time budget per frame (`tilesBudget.ts`);
  the GPU ground scales them to the exact zoom and draws each at its exact place. Tiles under new
  wear go stale and are repainted within the budget (`tilesWear.ts`). THE DENSITY STEPS
  (`tilesSteps.ts`, `tilesDensity.ts`; the default since 11-15): a tile is painted at the
  coarsest of the steps zoom 1 / 0.5 / 0.354 still as dense as the screen (painted at zoom 1 alone,
  a view zoomed out at 0.30 needed ~11x the tiles, each at full density); the look-ahead paints
  one tile a frame of the drawn step's widest view while nothing in view is missing; a tile goes
  to the GPU when it is first drawn; a new step is readied over the whole view - one paint
  and two uploads a frame - before it is drawn (no stand-in, no burst), with a gap between the
  zooms that switch each way (coarser below x1.1 inside the next step, finer from 0.95 of the
  drawn step's limit); the cache holds the real screen's widest view 1.25 times (a big PC screen
  shows ~300 zoom-1 tiles; 200 made it repaint a view each frame). The loading screen
  (`game/loading.ts readyStages`) starts the fly-in once the field is lined up, plans every
  tile of its path from the hand-over to the landing (64 views, each at its zoom's step, a ring
  round the landing) at the real screen, and paints then uploads them behind the bar; they are
  kept until the fly-in lands (`keepPlan`). The GPU sink says whether a picture is on it
  (`glground.ts has`).
  `tilesPalette.ts` builds the palette the GPU snaps to; `tilesShade.ts` the hill shading's
  heights and bands (drawn by `glshade.ts`).
- `render/ground/` paints into tiles: `art.ts` the per-surface art table, `prims.ts` pattern primitives,
  `zones.ts`, `covers.ts` (puddles, snow), `wear.ts` (worn cells, bumps, runoff).
- `render/textures.ts`: each surface's pattern is painted once at `TEX_PPM` (the car sprites' pixel
  size), seamless, and filled scaled to the zoom.
- Layers drawn each frame over the tiles: `road.ts` (lanes, kerbs, paint, slip roads), `marks.ts`,
  `objects.ts` (cones, tyres, tape, debris), `props.ts` + `props/` (fence, barriers, buildings, scenery,
  bridges), `cars.ts` with `carsprite.ts` (one cached sprite per livery; the redrawn bodies by car id in
  `carlooks.ts` LOOKS, the new cars' in `newcarlooks.ts` - the 911 GT3 R painted from its plan,
  a half width per column) and `cardamage.ts`,
  `particles.ts`.
- A rolled car (`render/rollbody.ts`) is drawn as a body: each column of the car a rounded
  cross-section (a superellipse as round as `physics/rollshape.ts` says), turned to one of 12
  angles, each picture row the nearest point of the turned outline. The outline (`closeRing`, the
  default since 11-14) gets points along each straight between two of its own, no more than
  0.45 px apart: a boxy car's superellipse bunches its points at the corners, and the rows between
  two far-apart points on a flat side or roof were left clear, the ground showing through
  (`tools/scratch/_rollholes.mjs`: every car, 12 angles, see-through pixels 11312 -> 4).
- Barriers (`render/props/fence.ts drawPropsBarriers`): one off-screen by its whole box (cached,
  `_rbb`) is skipped. Each is also cut into stretches of ~30 m with their
  own boxes (`_stretches`, cut again when a dent or tear gives it new points); only the stretches
  on screen are stroked (each run of them as one line, so the joins are the whole line's) and
  posted (each from the running distance the whole line has there: the same posts). Drawn whole:
  the pit wall (its painted blocks are one dash pattern along the line) and the rock wall.
- `render/light.ts`: the night layer, the ONLY light system (cars and props paint lamps, never
  light) - a light map the art buffer's size, the dark filled, headlight beams, lamp pools and the
  cars' lamp glows rubbed out, then the pools' warm tint and the glows' colour laid in; laid over
  the screen canvas once a frame under the HUD (nothing by day). The light level is
  `world/daylight.ts` (`?night=` fixes it, a test tool); the AI and traffic run headlights by it
  (`game/sim.ts updateFieldHeadlights`; the player's LIGHTS are their own).
- Lamps: `world/lamps.ts` makes the level's street lights (`lamps` data) and floodlight pylons
  into lamps with a solid post (`barriers.ts solidClamp`), lit from dusk; the night layer draws
  their pools, `render/props/lamps.ts` the street lights (overhead layer). A street course
  (`Level.streetLamps`, L.A. Lively) gets the plan's street lights along every straight of the
  lap, not only the start straight (`world/lampplan.ts`). The highway lays its
  own as the road grows (`highway/roadlamps.ts`: one every 34 m on alternating sides, kept
  in `level.lamps` by road distance and dropped behind with the window);
  `lamps.ts` keeps each streamed entry the same lamp, damage and all, while it is loaded.
- Solid lookups: `world/solidgrid.ts` files the level's solids and lamp posts by 16 m cell
  (`core/cellgrid.ts`, the one grid helper: the cover index and the bump grid use it too), so a
  car's clamp and a moving loose object test the few near them, in the lists' order (identical
  answers). Rebuilt when the level, its solids or its lamps change (the highway sets
  `solidsDirty` at each window rebuild). Highway: 4.3 -> 0.3 us a car-step with ~250 solids.
- Lane lookups: `world/zones.ts laneAt` files each lane's segments by 8 m cell over its box (built
  on first use, again when the highway rebuilds a lane's segments), so a lookup tests only its
  cell's segments, in order (identical answers: `tools/scratch/_cclaneat.mjs`).
- PERFPASS (the default since 11-14): the same game, quicker on big grids. The track-cut test
  `game/order.ts onLane` (every car, every step) asks
  `game/lanereach.ts`: each lane's segments filed by 16 m cell over its box grown by the lane's
  reach (half width + 1 m), built per lane on first use, again when its points or width change
  (a highway cut shortens them); a point tests its cell's segments with the walk's own test
  (identical answers on 39 levels, 332 544 edge points: `tools/scratch/_lanereach.mjs`).
  The barrier clamp (`world/barriers.ts clampToBarriers`) asks `world/barriergrid.ts`: a list's
  barriers by 16 m cell (a barrier in every cell one of its segments reaches, grown 8 m), and per
  barrier its segments by cell, both in order; the same meet test, box test, clamps, hit and dent
  as the walk, in the same order (a barrier met with no segment in reach changes nothing). Once a
  push takes the car out of its cell the rest of the call is walked whole; a car of 8 m or more
  is walked. A barrier's segment cells are built again with its segments (a dent, a tear, a
  restart: keyed on the segment list) and it is filed into any new cells at once; a list is
  filed again when its length changes or a new barrier is built. Identical: 252 000 clamps,
  62 111 hits, dents and tears (`tools/scratch/_barriergrid.mjs`, switch off vs on).
  The loose objects (`cones/coneStep.ts stepCones`) walk an awake list (`cones/coneSleep.ts`) in
  list order (by `_n`) instead of the whole list: an object at rest (`stillAtRest`, the gate the
  step already skipped on) sleeps at the end of the step; a car meeting it
  (`hitRestingObjects`) or a mover striking it (`coneGrid.ts pairWithResting`) wakes it if it
  stirred; new, spawned and burst objects join awake, a cull filters it, a restart wakes all; a
  tumbleweed with a breeze never sleeps. The movers are gathered from it. Identical objects and
  cars, 21 cars ploughing through 216-3 575 objects (`tools/scratch/_conebench.mjs`); Spa at
  rest 125 -> ~17 us a step in node.
  The night layer: the canopies' dark (`render/light.ts darkenCanopies`) traces the trees the
  prop grid holds round the light map grown by the level's largest canopy side
  (`render/trees.ts traceCanopiesNear`; the streaming highway walks the whole list), the season
  looked up once a call and each tree's kind kept; the event lights walk only the props of the
  kinds that light and the caravans among the loose objects (`render/eventglows.ts`, lists kept
  until the list changes, each kind still checked); the lamp pools and head glows make no list a
  lamp, and a head glow wholly off the map is not drawn (its alpha still set, in order). The prop
  grid files a prop by its drawn size, which a prop's lights outreach (a pit wall's lamps run
  110 m from its centre), so the light props are listed by kind rather than by the grid.
  The memory budget (`core/memorybudget.ts`): every canvas and bitmap the game makes is counted
  (`trackCanvas` at each of the 40 places one is made; width x height x 4 of those still held,
  summed when asked), plus LEVEL_MB for each lazy level built. Before `world/load.ts setLevel`
  builds a new level for play (not a thumbnail's light build), while the count is over
  MEMORY_BUDGET_MB the least recently played built level (not the one being left, not the one
  coming) goes back to its stub (its keys deleted, the stub's - `_build` with them - put back:
  built again on its next use), then any cached pictures registered with `onMemoryShort`; the
  drops are kept for the tools (`DROPS`). A dropped level rebuilds identically: all 49 lazy
  levels played twice through the budget, worldhash's fingerprint SAME but for the tape ids (a
  counter across builds) (`tools/scratch/_droprun.mjs`, `_droplevel.mjs`).
  MEASURED (`_memprobe.mjs`, 440 x 751 dpr 3, 20 AI, CPU x1; the budget forced to 0 to make every
  new build drop): five venue levels end at a 71 MB heap with drops vs 93 MB without (79 vs 94
  after a revisit); five stages / non-venue circuits 60 vs 65 MB. The canvases (72-113 MB) do not
  change with drops. A dropped level is built again in 1.1 s (Spa, CPU x1; 6.3 s at x4, its first
  build 1.8 / 8.9 s) and 0.3 s (Castle Kum). The venue cache (`world/venue.ts` builds) and the
  WeakMaps keyed by a level's parts keep some of a venue level's build after a drop.
- The game clock: `world/clock.ts` - a global time of day / season / moon
  (1 game day = 1 real hour, a season 7 days), saved in its own storage key, run by the sim step
  in events (`game/loop.ts`); it sets the sky (`daylight.ts setSky`: darkness and the dark's
  colour) that the night layer, the lamps and the headlights follow. TEST MODE setup: TIME OF DAY.
- `render/glground.ts`: THE ground (the game needs WebGL2; the iPhone's Safari has it since iOS
  15): the cached tiles are drawn by WebGL2 on a canvas UNDER the screen canvas, at full screen
  resolution with a sharp-pixel filter (crisp art pixels, no pixels dropped when the zoom changes);
  the art buffer is cleared to transparent so the GPU ground shows through, and everything else stays
  2D. A lost context (Safari under memory pressure, the app in the background) is rebuilt when the
  browser gives it back (`watchContext`); meanwhile the ground keeps its last frame.
- `render/glpaint.ts`: the floor and the zones painted on that GPU canvas every frame in world space
  at TEX_PPM texels per metre (the surface textures sampled per pixel, the tile palette applied by a
  lookup texture); `ground/zones.ts listGroundPatches` lists them, and the tiles then leave those
  fills transparent (`view.fillsOnGpu`). `glshade.ts` the hill shading, `glfield.ts` the cover
  field over it.
- Sharp cars (render.ts `drawSharpCarLayers`): the cars on the full-resolution
  screen canvas, not the art buffer. The art buffer under the cars is blitted, each car is painted
  facing +x into its own picture (`cars.ts paintCarPicture`, the same `drawPixelCar`, each sprite px
  a whole-number block) and turned and scaled onto the screen with smoothing; the art buffer then
  takes the overhead props and is blitted again. `render/glprogram.ts` builds the ground's shader.
- `render/screen.ts`: the screen canvas passes of a frame (the art buffer blits, the sharp cars, and
  the skid marks drawn on the screen between the deck and the layers above).

## Levels

Hand-made circuits in `world/levels/` (data: centreline, zones, props, barriers; `kit.ts` decorates a
traced track), generated stages from `stagegen.ts`, and the endless highway (`highway/`). Every name is a
parody pun (CLAUDE.md). A level is loaded by `world/load.ts`; `world/state.ts` holds the active one and its
lists (zones, bumps, props, barriers), which the physics and the renderer both read, so what you see is
what you drive on.
A LEVEL BUILT ON FIRST USE (`Level._build`: the venues, the set rally stages, the generator's
stage; `world/load.ts buildLevel`) read the floor of whatever level was set before it: `kit.ts`
`trackKit`'s `clear` and `rxDress`'s `free` keep a prop or a bale 5-6 m inside the live
`bounds.ts FLOOR`, so after Spa (613 m) the forest stage kept 26 more trees at its edge (853
props, 827 alone) and Croughed RX 41 more bales and stacks round Clervaux and Hawthorn (396
loose objects, 355 alone); and `load.ts tapePass` numbered its tape runs on from every level
taped before it. Since 11-15 (passed) the build runs in the standard
world (`bounds.ts inStandardFloor`: BASE_FLOOR, no rectangle, as when it is the first built; the
current level's floor put back after) and each level's tape runs number from 0, so every level

Croughed RX (546 m) keeps all 396 loose objects.

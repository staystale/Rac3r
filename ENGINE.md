# ENGINE - architecture overview

How the game is put together. Details live in the code comments of the file named; this page is the map.
Older design notes and measurements are in the git history of this file.

## Run, build, check

- `node serve.mjs` serves the game on http://localhost:8080. It transforms TypeScript with esbuild per
  request, so there is no build step while developing.
- `npm run build` (`tools/build.mjs`) makes the one bundled file for itch.io.
- `npm run verify` (`tools/verify.mjs`): syntax, encoding, tsc and lint (`tools/lint.mjs`, the CLAUDE.md
  section 2 rules).
- `npm run suite` runs the quick checks with pass / fail; `node tools/runall.mjs --full` adds the slow ones.
- Proof that a refactor changed nothing (save the reference on the base commit, then compare):
  - `tools/worldhash.mjs` - every level's data after load (`--highway 20` drives 20 km of motorway).
  - `tools/simhash.mjs` - every car's state every 0.5 s over 13 deterministic runs (AI, traffic, crash, cones).
  - `tools/renderhash.mjs` - the canvas pixels at fixed moments of 14 deterministic runs (CPU raster).
  - All three use `tools/lib/determinism.mjs`: a seeded `Math.random`, a fake clock and a stepped
    `requestAnimationFrame`.
- `tools/zoomcheck.mjs` measures how much the same patch of ground changes between zooms.

## One frame

`game/loop.js`, driven by `requestAnimationFrame`:

1. Input: `input.js` (or the autopilot / demo driver) gives one input state.
2. Fixed-step simulation: an accumulator runs `game/sim.js` in steps of `PHYSICS_STEP_SECONDS` (1/120 s):
   the player car (`vehicle.ts step`), AI cars (`game/ai.js`), highway streaming and traffic, contact,
   damage, rollovers, loose objects, wear, race rules and timing.
3. Interpolation of every car between the last two steps.
4. Draw: `renderer.frame()` (world into the art-pixel buffer, then to the screen), then the HUD.
5. Audio update and the fps meter.

## The car (`vehicle.ts` and `physics/`)

A top-down two-axle model with four tyre temperatures. `step(car, input, dt)`, in order:

1. `steerFrontWheels` - steering with speed-sensitive lock and self-aligning (`physics/powertrain.ts`).
2. `runPowertrain` - reverse, gears and shifting, engine rpm, throttle and brake demand.
3. `computeAxleLoads`, `computeLongitudinalDemand` - weight transfer and drive / brake per axle
   (`physics/loads.ts`).
4. `computeAxleForces` - tyre forces per axle: grip from surface, load and temperature, one continuous
   curve to the peak and a gentle slide, the friction circle, ABS, brake lock (`physics/tyres.ts`).
5. `ploughingForces`, `stabilityControl` - understeer plough and the ESC / TCS aids.
6. `bodyAccelerations`, `integrateYaw`, `lowSpeedBlend` - body motion; a blend near standstill.
7. `updateTyreTemps` (`physics/tyreheat.ts`), `advanceCar`, `writeTelemetry`.

The mods seam: every car has `car.mods` (`cars.ts defaultMods`: power, shiftTime, inertia, gripLat,
gripLong, brakeTorque, mass, rigidity), all 1.0 by default. Upgrades and tyres change these multipliers;
the model reads them and nothing else.

Surfaces come from the ground under each wheel (`world/wear.ts groundAt`): the surface's grip and drag,
any cover (snow, ice, puddle) and the wear state of the cell.

## Drawing (`render.ts` and `render/`)

- Pixel art: the world is drawn into a low-resolution art-pixel buffer (about 15 art px per metre at
  zoom 1) and blitted to the screen with smoothing off. The camera is snapped to whole art pixels and the
  leftover fraction is applied when blitting. The HUD is drawn afterwards at full resolution.
- `render/camera.ts`: follow with look-ahead, speed zoom (`ZOOM_MIN` 0.30), the level fly-in and the
  whole-level overview picture used during it.
- `render/tiles.ts`: the static ground (floor, zones, track ribbon) is painted into cached tiles at fixed
  zoom steps (2 per doubling) within a time budget per frame (`tilesPalette.ts` palette snap,
  `tilesShade.ts` hill shading on a world grid). A missing tile shows the previous step's tile scaled.
- `render/ground/` paints into tiles: `art.ts` the per-surface art table, `prims.ts` pattern primitives,
  `zones.ts`, `covers.ts` (puddles, snow), `wear.ts` (worn cells, bumps, runoff).
- `render/textures.ts`: each surface's pattern is painted once at `TEX_PPM` (the car sprites' pixel
  size), seamless, and filled scaled to the zoom.
- Layers drawn each frame over the tiles: `road.ts` (lanes, kerbs, paint, slip roads), `marks.js`,
  `objects.ts` (cones, tyres, tape, debris), `props.ts` + `props/` (fence, barriers, buildings, scenery,
  bridges), `cars.ts` with `carsprite.ts` (one cached sprite per livery) and `cardamage.ts`,
  `particles.ts`.
- `render/glground.ts` (default; `?glground=0` = the old path): the cached tiles are drawn by WebGL2 on a
  canvas UNDER the screen canvas, at full screen resolution with a sharp-pixel filter (crisp art pixels,
  no pixels dropped when the zoom changes); the art buffer is cleared to transparent so the GPU ground
  shows through, and everything else stays 2D. Without WebGL2 the tiles go into the art buffer as before.
  Step B (the ground painting itself on the GPU) is in TODO.md "GROUND ON THE GPU".

## Levels

Hand-made circuits in `world/levels/` (data: centreline, zones, props, barriers; `kit.ts` decorates a
traced track), generated stages from `stagegen.js`, and the endless highway (`highway/`). Every name is a
parody pun (CLAUDE.md). A level is loaded by `world/load.ts`; `world/state.ts` holds the active one and its
lists (zones, bumps, props, barriers), which the physics and the renderer both read, so what you see is
what you drive on.
